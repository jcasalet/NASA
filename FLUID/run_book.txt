STEPS TO DEPLOY FLUID IN AWS

=======
SECTION 1: CREATE INSTANCES ON AWS
=======

1. create AWS instance template (in AWS EC2 console) using the following parameters:
	- OS = redhat 8.4 hvm x86_64
	- type = t2.large (2 vcpu, 8gb ram, $0.0928 per hour)
	- keypair = jupyterlab
	- security group = jupyterlab (this will open ingress ports 22, 8888 from any ip; allow icmp)
	- root disk = 100gb EBS volume type gp2

2. launch 6 instances from template (in AWS EC2 console)
- Name the instances according to the following list: agg-earth, colab-earth, colab-shim,  colab-iss, agg-iss, tds

** note no tds in this deployment -- getting files directly from agg-iss and sending them to colab-shim

SECTION 3: RUN EXPERIMENT - EXECUTE THE COMMANDS ON THE SPECIFIED NODES
================================================

IMPORTANT: If you stop/restarted any of the AWS nodes during this process, they will be allocated new public IP addresses. In this case, you must update the IP addresses in the fluid-network.sh file (see Step 15) and the /etc/hosts file (see step 3) on each of the nodes before running the experiments.

ON ALL NODES (and in any order) EXCEPT THE BRIDGE NODE perform steps 1 & 2 


1 Login as fluid and clean up from previous runs... clear workspace, kill active containers 
$ su - fluid
$ docker stop $(docker ps -a -q)
$ rm -rf data/WORKSPACE/workspace

1.5 ON ALL NODES, update /etc/hosts if necessary


2. Launch the containers
$ cd scripts
$ ./runDocker-notls-shim.sh -r $(hostname) 

ONLY ON THE BRIDGE NODE perform step 3.

3. Start bridge node syncing (after having started all the other containers)

$ su - fluid
$ pkill oursync.sh
$ cd scripts
$ ./oursync.sh $HOSTNAME

4. Monitor standard output for completion and get results. You'll get your prompt back on agg-earth, colab-earth, and colab-iss after job is complete.

5. Upon completion, retrieve results from agg-earth 

$ su - fluid
$ cp ~/scripts/get_results* ~/crisp
$ cd ~/crisp
$ ./get_results.sh
